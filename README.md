# sshtunnel一键脚本

通过交互菜单创建和管理 SSH 隧道账户，设置独立端口、公钥或密码认证、转发范围及可选的 fail2ban 防护。账户仅用于隧道，不能登录 Shell、执行命令或使用 SFTP/SCP。

## 运行要求

| 系统 | 服务管理器 | 最低版本 |
| --- | --- | --- |
| Alpine | OpenRC | 3.18 |
| Debian | systemd | 9 |
| Ubuntu | systemd | 18.04 |

需要 root 权限、交互终端和正常运行的服务管理器。只有基础文件、没有启动 init 的容器镜像不能直接使用。请先备份 SSH 配置，保留管理员连接或控制台，再进行安装和配置。

脚本使用 Python 3.5+ 标准库，兼容 BusyBox `sh`，无需 Bash、pip、虚拟环境或编译工具。缺少核心依赖时会尝试安装，Alpine 的共享库和 OpenRC 拆分包由 APK 处理。旧发行版需要自行配置可用的软件源；兼容旧版本不代表该系统仍在获得安全更新。

本地转发和 SOCKS5 可用于旧 OpenSSH。远程转发需要 OpenSSH 7.8+ 的 `PermitListen` 支持，缺少时不会开放该功能。可选的 fail2ban 防护要求 0.11+，还需要容器具备相应的 iptables/ip6tables 权限。

## 下载与运行

在自己管理的目录中，选择一种方式下载：

```sh
curl -fL --proto '=https' --tlsv1.2 -o main.sh https://raw.githubusercontent.com/IwasakiYouko/SSHTunnel-One-Click/main/main.sh
```

```sh
wget -O main.sh https://raw.githubusercontent.com/IwasakiYouko/SSHTunnel-One-Click/main/main.sh
```

确认下载成功并检查脚本后，以 root 运行：

```sh
sh main.sh
```

使用 sudo 的系统可运行 `sudo sh main.sh`。安装后的默认管理命令为 `ssht`；若名称已被占用，脚本会要求另选名称。

```sh
ssht
```

下载链接指向 `main` 分支当前版本，再次下载会覆盖当前目录的同名文件。请先下载再运行，菜单需要从终端读取输入，`curl | sh` 和 `wget -O- | sh` 会被拒绝。

| 参数 | 用途 |
| --- | --- |
| `--help` | 查看用法 |
| `--light` | 强制使用轻量模式 |
| `--no-update` | 跳过启动时的软件包操作 |
| `--update` | 强制检查依赖更新 |

例如 `ssht --light --no-update`。后两项不能同时使用；从菜单安装依赖或启用 fail2ban，仍可能联网。

## 账户与转发

- 每个账户使用独立的 SSH 端口和服务。接入端口默认 2222，可选范围为 1024～65535。
- 支持公钥、密码或公钥加密码认证。可导入多把客户端公钥，也可生成 Ed25519 密钥；替换公钥会撤销全部旧公钥。
- 默认允许本地及动态 TCP 转发。`PermitOpen any` 可访问任意目标，包括服务器内网；有隔离要求时，请指定明确的 `host:port`。
- 可选远程转发，并限制服务器监听地址和端口。对外开放远程监听默认关闭。
- SOCKS5 客户端示例默认关闭。打开示例不会在服务器新增 SOCKS5 监听；SSH 动态转发承载 TCP，不提供通用 UDP 转发。
- Shell、命令执行、PTY、SFTP/SCP、sudo、Agent、X11、Unix Socket 转发和 TUN 均被禁用，菜单中不能开启。
- fail2ban 默认关闭。启用后默认在 600 秒内失败 5 次时封禁 3600 秒，可修改阈值、时间和白名单；新规则默认只放行回环地址。

修改权限、认证方式或重启服务会断开该账户已有连接。删除账户会删除专属配置、规则和日志，不能回滚。已导出的凭证需自行清理。

## 小内存容器

可见内存不超过 256 MiB，或 `/var` 所在文件系统总容量不超过 1 GiB 时，自动启用轻量模式。内存判断会读取 LXC 可见的 cgroup 限制。

轻量模式在依赖齐全时跳过启动更新，将每个账户待认证连接上限降到 4，认证宽限期缩短为 20 秒。未启用 fail2ban 时关闭常规连接日志，服务只保留 SSH 进程；管理菜单退出后，Python 进程随之结束。已有账户需重新应用配置才能使用新的设置。

1 核、128 MiB 内存、512 MiB 硬盘的容器建议从单账户、公钥认证开始，保持 fail2ban 关闭。64 MiB 可以按同样设置尝试，但基础系统、并发连接和安装依赖都要占用内存。512 MiB 也是整个系统的磁盘额度，需要留出下载和解包空间，不能保证任意容器模板都装得下、跑得稳。

## 日志额度

`/var/log/ssht/` 下的隧道日志默认共用所在文件系统总容量的 10%。例如文件系统为 512 MiB，默认额度约为 51.2 MiB。主菜单“日志总额度”可改为自定义 MiB，或恢复自动计算。

额度按账户数均分，每个账户只有一个日志文件。每条记录写入前检查大小，放不下就清空该账户旧日志后写入，单条记录超过额度时截断。降低额度会立即清空超额文件，并删除旧版留下的数字编号日志归档。日志不会额外压缩或归档，需要保留时请先导出。

开启日志会增加少量 Shell/awk 进程和写入开销；旧版 mawk 还需要逐条调用 `date` 生成时间戳。轻量模式关闭日志时不保留这些处理进程。系统原有 SSH、fail2ban 的共享日志和数据库由各自服务管理，不计入本脚本的隧道日志额度。

## 对现有系统的影响

脚本创建专用组 `ssht-tunnel`，在 `/etc/ssh/sshd_config` 顶部维护 `DenyGroups ssht-tunnel`，防止隧道账户通过原 SSH 入口绕过权限限制。修改前会备份并校验。原入口需使用发行版标准的 `ssh`/`sshd` 服务和默认配置；已有同名账户或组不会被接管。Dropbear 和其他自定义入口不在管理范围内。

软件更新只针对脚本所需的包，先模拟计划并保护无关已安装包的版本；遇到删除、降级或无关升级就停止。不替换软件源，不关闭签名校验，不执行系统级升级或自动移除软件包。APT 使用自有临时索引和下载目录，完成后清理。

软件包安装脚本可能重启系统服务。隧道与原 SSH 共用 OpenSSH 软件包，更新可能影响管理员连接；已有隧道还需重启才能使用新版程序。Alpine 若留下 `.ssht-update-guard`，先用 `apk del --simulate .ssht-update-guard` 检查，确认只删除保护包后再处理。

fail2ban 为每个账户建立独立 jail，修改时仅操作该账户的规则，其他 jail 保留。是否真正拦截失败登录，仍需在目标环境验收。脚本不自动开放云安全组或防火墙端口，请按最终配置放行对应 TCP 端口。

## 凭证与恢复

| 位置 | 内容 |
| --- | --- |
| `/usr/local/lib/ssht/` | 管理脚本和服务启动脚本 |
| `/etc/ssht/` | 全局设置、账户记录、SSH 配置、日志额度及主机私钥 |
| `/var/lib/ssht/` | root 管理的公钥文件和账户 home |
| `/var/log/ssht/` | 隧道日志 |
| `/etc/fail2ban/jail.d/ssht-<账户>.local` | 账户防护规则 |
| `/etc/systemd/system/ssht-<账户>.service` | Debian/Ubuntu 服务 |
| `/etc/init.d/ssht-<账户>` | Alpine 服务 |
| `/root/ssht-credentials/<账户>-<随机后缀>` | 默认凭证导出目录 |

凭证目录权限为 700，文件为 600，须归 root 所有。导入公钥时可不导出凭证；在服务器生成客户端私钥时，必须先保存再部署。明文密码默认不保存，私钥口令始终不保存。连接前核对服务器主机指纹，妥善转移私钥；旧导出文件不会随配置变化自动更新。

修改失败时，脚本尝试恢复文件、密码哈希和服务状态，已断开的连接需由客户端重新建立。公共依赖、管理命令、专用组和原 SSH 拒绝规则不随账户修改回滚。

若出现 `/etc/ssht/txn-*`，表示有未完成事务，脚本会停止继续写入。不要直接删除目录绕过检查：

1. 停止对应 `ssht-<账户>` 服务，确认无遗留连接，保留整个事务目录副本。
2. 阅读 `account.json`，核对账户名、UID、是否本次创建、原启停状态。文件可能含旧密码哈希，应按秘密文件保管；UID 为 null 时须先确认账户是否已创建。
3. 按 `manifest.json` 恢复文件：`backup` 为文件名时，恢复其内容及 `mode`；为 null 时，只删除确认属于本次事务的新文件。
4. 必要时用 `chpasswd -e` 的标准输入恢复旧哈希，不将哈希放进命令参数或共享日志；检查账户密码日期。清理新建账户前再次核对 UID、组和 home。
5. 校验 SSH 与 fail2ban 配置，systemd 执行 `daemon-reload`，恢复原服务和 jail 状态。确认管理员入口可用后，再移走事务目录。

删除中断时，账户记录会保留“删除中”状态，可再次进入删除菜单完成清理。

## 兼容性与验证范围

Ubuntu 24.04、Debian 13、Alpine 3.23 的容器检查覆盖依赖安装、账户操作、配置与密码哈希回滚、SSH 监听、日志大小控制和 fail2ban 日志识别。另用 Debian 9、Ubuntu 18.04、Alpine 3.18 的 x86_64 原版 Python、OpenSSH 和 awk 检查了核心操作与配置。

在 64 MiB 进程地址空间限制下，管理程序测得内存峰值约 15～17 MiB，关闭日志的空闲 SSH 服务约占 4.4～8 MiB。这不包含基础系统、依赖安装及认证后的连接，也不能视为整机 64/128 MiB 内存、512 MiB 磁盘配额的 LXC 验收结果。

测试环境未完整启动 init，且禁止 OpenSSH 认证所需的 `chroot`。真实登录、数据转发、完整服务启停和防火墙封禁仍需在目标系统确认。旧版程序检查也未执行旧发行版的软件包维护脚本或完整引导过程。
